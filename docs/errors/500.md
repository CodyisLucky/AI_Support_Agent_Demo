# Error 500

## What the shopper sees

"Something went wrong on our side. Nothing was changed. Try again."

The shop sends them back to the shop. The cart is unchanged.

## When it happens

A request hit an error the shop does not have a more specific code for. Checkout with card `4000000000000500` does this on purpose. Any other unhandled failure does it too.

This is not a decline and not a processor timeout. Those are 201 and 507.

## Likely cause

The payment response was not one the shop could read, or some other bug fired. `detail` is the Python error type, such as `RuntimeError`. It does not include the card number or the password.

## What to try

Try the same action once more. If it was checkout, use a different card number. Do not tell them the charge went through. Nothing was saved for this attempt.

## Log line

`code` is `500`. `user_id` is the signed-in account, or `null` for a guest. `detail` is the error type.
