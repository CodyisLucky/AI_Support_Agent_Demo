# Error 509

## What the shopper sees

The Help chat says which limit was reached, when it resets if it does, that nothing in their account or orders was changed, and that they can email the team. The wording depends on the limit:

- **Too many messages too fast:** "You're sending messages faster than our assistant can answer. Wait a minute, then try again." The message is not saved.
- **Too many messages from one network in an hour:** asks them to try later or email the team. The message is not saved.
- **Chat message limit:** the chat has reached its message limit; closing the browser and coming back starts a new chat.
- **Daily cap:** the assistant reached its daily usage limit and is available again at midnight UTC. The message is saved with a note from the shop.
- **Reply token limit:** the question needed more lookups than one reply allows, so the assistant stopped rather than guess and the chat is passed to the team.
- **Off-topic requests:** after several requests unrelated to the shop, the assistant is paused for that chat. Each earlier off-topic request got a short decline, and the one before the pause warned them.

## When it happens

These safeguards keep the chat a shopping helper and cap what it can cost the business. Every limit is a setting in `agent.env`:

| Limit | Setting | Default |
|---|---|---|
| Messages per minute in one chat | `AGENT_RATE_PER_MINUTE` | 6 |
| Messages per hour from one network | `AGENT_RATE_PER_HOUR_PER_IP` | 60 |
| Messages per chat | `AGENT_MAX_MESSAGES_PER_CHAT` | 30 |
| Characters per message | `AGENT_MAX_MESSAGE_CHARS` | 1,000 (a plain error, not 509) |
| Tokens per reply, across lookups | `AGENT_MAX_TOKENS_PER_REPLY` | 60,000 |
| Off-topic requests before a pause | `AGENT_OFF_TOPIC_LIMIT` | 3 |
| Daily spend, all visitors | `AGENT_DAILY_BUDGET_USD` | $5 (0 = off) |
| Daily spend, one visitor | `AGENT_VISITOR_DAILY_BUDGET_USD` | $1 (0 = off) |

A visitor is their account when signed in, otherwise their IP address, stored only as a hash under a key that changes daily. Spend is the shop's own estimate from token counts. Caps are checked before each reply, so the reply that crosses a cap finishes.

## Likely cause

Ordinary heavy use, a script flooding the chat, someone trying to use the chat as a general AI assistant, or a cap set low for the day's traffic.

## What to try

Wait for the limit to reset, or email the team with the conversation ID. Do not suggest clearing cookies to get around a limit.

## Log line

`code` is `509`. `user_id` is the signed-in account, or `null` for a guest. `detail` names the limit, such as `rate limit: messages per minute in one chat` or `daily cap for this visitor reached`. A rate limit writes one line per window, not one per refused message. The log never stores the IP address.
